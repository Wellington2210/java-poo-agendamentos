00 · antes de tudo

O que é, afinal, "orientação a objetos"?

Imagine a barbearia funcionando só no papel, sem computador. Toda vez que um cliente marca um horário, o dono pega uma ficha em branco e preenche: nome do cliente, serviço, data, horário. Cada cliente novo ganha uma ficha nova — as fichas não se misturam.

Programação orientada a objetos (POO) é exatamente essa ideia, só que dentro do computador:

  • A ficha em branco, o modelo que diz quais campos existem, é o que chamamos de classe.
  • Cada ficha preenchida, com dados de um cliente específico, é o que chamamos de objeto.

Toda a "revisão de Java" que vem a seguir é, no fundo, aprender a: (1) desenhar a ficha em branco, (2) preencher fichas, (3) decidir quem pode rabiscar em cima delas depois de prontas, e (4) fazer a ficha reagir sozinha a determinadas ações — como "reagendar" ou "cancelar".

POR QUE ISSO IMPORTA Sem POO, o código de um sistema de agendamentos viraria uma bagunça de variáveis soltas (nomeCliente1, nomeCliente2, servico1, servico2...) sem nenhuma organização. A classe agrupa tudo que pertence a "um agendamento" num único lugar, e cada objeto é uma cópia independente dessa estrutura.
01 · fundamentos

Classe

Uma classe é o molde, o modelo usado para criar objetos. Ela só descreve quais informações um agendamento vai ter — ela não é, sozinha, um agendamento de verdade.

PENSE ASSIM A classe é a ficha impressa em branco, com os campos "Nome do cliente: ____", "Serviço: ____", "Data: ____", "Horário: ____". Ninguém marcou hora nenhuma ainda — é só o formulário.
public class Agendamento { String nomeCliente; String servico; String data; String horario; }

Linha por linha

public class
Diz ao Java "estou criando uma nova classe, e ela pode ser usada por qualquer outra parte do programa".
Agendamento
O nome que demos a essa classe — por convenção, começa com letra maiúscula.
{ ... }
As chaves marcam onde a classe começa e onde ela termina. Tudo o que pertence ao "molde" fica dentro delas.
String nomeCliente;
Declara um campo chamado nomeCliente, que vai guardar um texto (String = texto, em Java).
Agendamento ├── nomeCliente ├── servico ├── data └── horario

Repare que a classe não guarda nenhum valor real — nenhum nome, nenhuma data. Ela só define a "forma" que um agendamento vai ter.

02 · fundamentos

Objeto

O objeto é uma ficha preenchida, criada a partir da classe. Cada vez que você escreve new, o Java reserva um espaço novo na memória e cria uma cópia independente da estrutura descrita na classe.

Agendamento agendamento1 = new Agendamento();
Agendamento
O tipo da variável — diz que agendamento1 vai guardar um objeto desse molde.
agendamento1
O nome que demos a essa variável — é como um "rótulo" que aponta para o objeto criado.
new Agendamento()
O comando que efetivamente cria o objeto na memória. Sem o new, nada é criado.

Logo depois de criado, o objeto existe, mas ainda está "vazio" — todos os campos de texto começam com o valor especial null (nenhum valor):

agendamento1 │ ▼ ┌────────────────────┐ │ Agendamento │ │ nomeCliente = null │ │ servico = null │ │ data = null │ │ horario = null │ └────────────────────┘
O ponto mais importante desta seção: se você criar dois objetos a partir da mesma classe, cada um vive de forma totalmente separada. Preencher a ficha de um cliente não afeta a ficha de outro.
Agendamento agendamento1 = new Agendamento(); Agendamento agendamento2 = new Agendamento();
agendamento1 → Objeto A
agendamento2 → Objeto B
Se você mudar o nome do cliente em agendamento1, o que acontece com agendamento2? testar
Nada. São objetos diferentes, cada um com sua própria cópia dos atributos — mudar um não tem qualquer efeito sobre o outro, mesmo que os dois tenham vindo da mesma classe.
03 · fundamentos

Atributos

Atributos são os dados guardados dentro de um objeto — os campos que a classe definiu (nomeCliente, servico, data, horario). É neles que moram os valores reais, específicos daquele objeto.

public class Agendamento { String nomeCliente; String servico; String data; String horario; }

Depois de criar o objeto, podemos atribuir valores a esses campos usando o ponto (.), que significa "dentro deste objeto":

agendamento1.nomeCliente = "Wellington"; agendamento1.servico = "Corte";
PENSE ASSIM Se a classe é a ficha em branco, os atributos são as linhas dela. E agendamento1.nomeCliente = "Wellington" é o mesmo que pegar a ficha do agendamento1 e escrever "Wellington" na linha "Nome do cliente".
04 · fundamentos

Métodos

Se atributos são os dados que o objeto tem, métodos são as ações que o objeto faz. Um método é basicamente uma receita de passos que o objeto sabe executar.

public void imprimir() { System.out.println(this.nomeCliente); System.out.println(this.servico); }
public void
public = qualquer parte do programa pode chamar este método. void = ele não devolve nenhum valor de volta, só executa uma ação.
imprimir()
O nome do método. Os parênteses vazios dizem que ele não precisa receber nada para funcionar.
System.out.println(...)
Comando pronto do Java para exibir um texto no console.

Para executar o método em um objeto específico, chamamos com o ponto:

agendamento1.imprimir();

Tem × Faz

TEM (atributos)

nomeCliente
servico
data
horario

FAZ (métodos)

imprimir()
reagendar()
cancelar()

Todo objeto na POO combina essas duas coisas: dados guardados e ações que sabem manipular esses dados.

05 · fundamentos

Parâmetros

Às vezes um método precisa de uma informação vinda de fora para conseguir fazer seu trabalho. Essa informação é recebida através de um parâmetro — uma variável temporária declarada entre os parênteses do método.

public void reagendar(String novoHorario) { this.horario = novoHorario; }

String novoHorario é o parâmetro: ele existe apenas durante a execução do método, como uma "caixinha temporária" que recebe o valor passado na chamada.

// chamando o método e passando um valor: agendamento.reagendar("14:30");

O que acontece, passo a passo, quando essa linha executa:

"14:30"
→
novoHorario
→
this.horario
  1. O texto "14:30" é enviado na chamada do método.
  2. Ele é recebido dentro do método pelo parâmetro novoHorario.
  3. A linha this.horario = novoHorario copia esse valor para o atributo horario do objeto, tornando a mudança permanente.
06 · fundamentos

this

this é uma palavra especial do Java que significa "o objeto atual" — o objeto específico em que o método está sendo executado naquele momento. Ele existe principalmente para resolver um problema de nomes repetidos.

O PROBLEMA QUE O THIS RESOLVE Imagine que o atributo do objeto se chama servico, e o parâmetro que chega de fora também se chama servico. Java precisa de um jeito de diferenciar "o servico que já pertence a este objeto" do "servico que acabou de chegar como parâmetro". É exatamente isso que o this. indica.
public void setServico(String servico) { this.servico = servico; }
this.servico
o atributo — o campo que já existe dentro deste objeto, guardado permanentemente.
servico (à direita)
o parâmetro — o valor temporário que chegou de fora, na chamada do método.

Uma forma simples de ler essa linha em voz alta: "o atributo servico deste objeto recebe o valor do parâmetro servico."

agendamento.setServico("Corte"); // servico (parâmetro) = "Corte" // ↓ // this.servico = "Corte" // ↓ // atributo do objeto = "Corte"
O que aconteceria se você escrevesse só servico = servico;, sem o this? testar
O atributo do objeto nunca seria alterado. Como as duas palavras servico ali seriam entendidas como o mesmo parâmetro local, a linha equivaleria a "o parâmetro recebe a si mesmo" — o valor nunca chegaria até o atributo. O this é o que aponta explicitamente para o atributo do objeto.
07 · encapsulamento

public e private

Até agora, tratamos os atributos como se qualquer parte do programa pudesse acessá-los livremente. Na prática, isso é perigoso — e é para controlar esse acesso que existem os modificadores de acesso: public e private.

PENSE ASSIM public é como deixar a ficha do cliente em cima do balcão — qualquer funcionário pode pegar e rabiscar. private é guardar a ficha numa gaveta trancada: só a própria recepção (a própria classe) tem a chave para mexer nela diretamente.

public

cliente.nome = "João"; // funciona de fora // da classe

private

cliente.nome = "João"; // erro de // compilação

Se o atributo for private, ele só pode ser alterado por um código que está dentro da própria classe:

public class Cliente { private String nome; public void alterarNome(String nome) { this.nome = nome; } }

Aqui, nome continua protegido de acesso direto de fora — mas o próprio método alterarNome, que faz parte da classe, consegue mexer nele sem problema.

Regra para guardar: private permite acesso direto somente dentro da própria classe. De fora, o acesso precisa passar por um método público.
08 · encapsulamento

Getter

Se um atributo é private, como outra parte do programa consegue ao menos ler o valor dele? A resposta é o getter: um método público, criado só para devolver o valor de um atributo privado.

public String getNome() { return this.nome; }
public String
Este método pode ser chamado de fora, e ele devolve um valor do tipo texto.
getNome()
O nome segue a convenção "get" + o nome do atributo com inicial maiúscula — isso não é obrigatório, mas é o padrão que todo programador Java espera ver.
return this.nome;
return devolve o valor pedido para quem chamou o método.
System.out.println(cliente.getNome());
getNome()
→
return this.nome
→
"Wellington"
09 · encapsulamento

Setter

Da mesma forma que o getter serve para ler um atributo privado, o setter serve para alterá-lo de forma controlada — através de um método público, e não diretamente.

public void setNome(String nome) { this.nome = nome; } // uso: cliente.setNome("Wellington");
"Wellington"
→
parâmetro nome
→
this.nome = nome
→
atributo nome

Repare que o getter e o setter, juntos, são a "porta de entrada e saída" oficial para um atributo privado. Nas próximas seções veremos por que isso é mais poderoso do que parece.

10 · pilar da POO

Encapsulamento

Encapsulamento é um dos pilares centrais da POO, e é a ideia que dá sentido a tudo que vimos nas últimas três seções. Em resumo: o objeto protege seu próprio estado interno e decide, ele mesmo, como e quando esse estado pode mudar.

Em vez de deixar qualquer parte do programa alterar um atributo livremente...

agendamento.horario = "14:30"; // direto assim, sem nenhuma verificação

...criamos uma operação com nome e com regras, que a classe controla:

public void reagendar(String novoHorario) { if (novoHorario == null) { return; } this.horario = novoHorario; } // uso: agendamento.reagendar("14:30");

Esse pequeno if já é uma regra de negócio: se alguém tentar reagendar passando um horário vazio (null), o método simplesmente ignora o pedido (return sai do método sem fazer nada). No futuro, esse mesmo método pode crescer com mais verificações, sem que o resto do sistema precise mudar:

public void reagendar(String novoHorario) { if (novoHorario == null) { return; } // verificar disponibilidade // verificar se foi cancelado // verificar se horário já passou this.horario = novoHorario; }
PENSE ASSIM É a diferença entre deixar qualquer cliente rabiscar direto na agenda do salão, e obrigar toda mudança de horário a passar pela recepcionista — que sabe as regras da casa (não marcar em cima de outro horário, não marcar num dia fechado, etc.).
Por que não deixar agendamento.horario = "14:30" diretamente, se no final o valor fica o mesmo? testar
Porque, alterando direto, nenhuma regra de negócio seria aplicada — qualquer parte do sistema poderia gravar um horário inválido, duplicado, ou de um agendamento já cancelado, sem que ninguém percebesse. Passando pelo método reagendar(), a própria classe garante que as verificações aconteçam sempre, em todos os lugares que chamarem esse método.
11 · pilar da POO

Encapsulamento não é só getter e setter

É comum, quando se está aprendendo, achar que "encapsular" significa apenas criar um getter e um setter para cada atributo privado. Mas isso não é sempre a melhor solução — às vezes um setter genérico devolve todo o poder que o encapsulamento deveria tirar.

Um exemplo clássico é um saldo bancário:

public void setSaldo(double saldo) { this.saldo = saldo; } // qualquer parte do programa poderia fazer: conta.setSaldo(1000000);

Um setter assim permite que qualquer código simplesmente sobrescreva o saldo para qualquer valor, sem passar por depósito, saque ou qualquer verificação. É mais seguro expor uma operação com significado real:

public void depositar(double valor) { if (valor > 0) { this.saldo += valor; } }
No projeto da barbearia, o mesmo raciocínio vale para o horário: agendamento.reagendar("15:00") é preferível a agendamento.setHorario("15:00"), porque reagendar() representa uma operação real do negócio, com nome e regras próprias — e não apenas uma troca crua de valor.

A pergunta a se fazer sempre: "esse método representa algo que realmente acontece no mundo real do meu sistema, ou só está expondo o atributo com outro nome?"

12 · criação de objetos

Construtor

Até agora criávamos o objeto vazio (new Agendamento()) e depois preenchíamos os atributos um por um. O construtor permite fazer isso tudo de uma vez: o objeto já nasce pronto, com os dados corretos desde o primeiro instante em que existe.

public Agendamento( String nomeCliente, String servico, String data, String horario) { this.nomeCliente = nomeCliente; this.servico = servico; this.data = data; this.horario = horario; }

Repare que cada parâmetro recebido é copiado para o atributo correspondente com a ajuda do this — exatamente a mesma lógica da seção 06.

Agendamento agendamento = new Agendamento( "Wellington", "Corte", "07/10", "09:10" );
new Agendamento(...)

parâmetros recebem valores
→
atributos preenchidos
PENSE ASSIM Sem construtor: você pega a ficha em branco e preenche linha por linha, depois de já tê-la em mãos. Com construtor: você entrega os dados na hora de imprimir a ficha, e ela já sai do balcão preenchida.
13 · criação de objetos

Construtor parece método, mas não é

Visualmente, um construtor lembra bastante um método — os dois têm parênteses, parâmetros e um corpo entre chaves. Mas há duas diferenças que valem a pena decorar.

Método

public void reagendar(String h) { }

Construtor

public Agendamento(String h) { }
  1. Tipo de retorno: um método sempre tem um tipo de retorno, mesmo que seja void (nenhum retorno). Um construtor nunca tem — nem void aparece antes do nome.
  2. Nome: um método pode ter qualquer nome (reagendar, cancelar, imprimir...). Um construtor precisa ter exatamente o mesmo nome da classe.

Em resumo: o construtor participa do momento em que o objeto nasce. O método trabalha em um objeto que já existe.

14 · criação de objetos

Construtor padrão

Se você escrever uma classe sem nenhum construtor...

public class Agendamento { }

...o Java, nos bastidores, disponibiliza automaticamente um construtor vazio, equivalente a este:

public Agendamento() { }

É por isso que sempre funcionou escrever new Agendamento(); mesmo sem termos escrito nenhum construtor à mão até a seção 12.

Mas atenção a essa pegadinha comum: assim que você escreve manualmente qualquer construtor com parâmetros, o Java deixa de fornecer o construtor vazio automaticamente.
public Agendamento(String nome) { this.nome = nome; } // a partir de agora, isso dá erro de compilação: new Agendamento();

Se você precisa dos dois — um construtor vazio e um com parâmetros — é preciso escrever ambos explicitamente:

public Agendamento() { } public Agendamento(String nome) { this.nome = nome; }
15 · criação de objetos

Sobrecarga

Vimos, na seção anterior, dois construtores com o mesmo nome (Agendamento). Isso é permitido em Java e tem um nome: sobrecarga (em inglês, overload). Ela funciona tanto para métodos quanto para construtores.

A regra é simples: você pode repetir o mesmo nome quantas vezes quiser, desde que a lista de parâmetros seja diferente entre as versões (quantidade ou tipo).

public Agendamento() { } public Agendamento(String nome) { } public Agendamento(String nome, String servico) { }

Quando você escreve new Agendamento("Wellington"), o Java olha para os argumentos passados (aqui, um único texto) e escolhe automaticamente a versão do construtor que combina com eles — nesse caso, a segunda.

16 · criação de objetos

Construtor + getter, sem setter

Uma pergunta comum de quem está começando: "todo atributo privado precisa de um getter e um setter?" Não. É perfeitamente válido — e muitas vezes desejável — que um objeto receba seus dados apenas no construtor, e depois só permita consultar esses dados, sem permitir alterá-los.

public class Agendamento { private String nomeCliente; private String servico; public Agendamento(String nomeCliente, String servico) { this.nomeCliente = nomeCliente; this.servico = servico; } public String getNomeCliente() { return this.nomeCliente; } public String getServico() { return this.servico; } }
agendamento.getServico(); // ok, funciona normalmente agendamento.setServico("Barba"); // erro: esse método nunca foi criado — e pode ser proposital

Nem sempre a ausência de um setter é um esquecimento. Às vezes é uma decisão de projeto: esse dado nasce junto com o objeto e nunca deveria mudar depois.

17 · síntese

Mudança de estado

Para fechar, um ponto que costuma confundir quem está começando: usar um setter para alterar um atributo não cria um objeto novo. É o mesmo objeto que continua existindo, só que agora com um valor diferente guardado dentro dele — isso é chamado de mudança de estado.

Agendamento agendamento = new Agendamento("João", "Corte", "08/09", "15:00"); // neste momento: servico = "Corte" agendamento.setServico("Barba"); // a partir de agora: servico = "Barba"
PENSE ASSIM É como riscar o campo "serviço" na ficha e escrever outro por cima. A ficha continua sendo a mesma ficha, com o mesmo cliente e o mesmo número — só uma informação dentro dela mudou.
Depois de setServico("Barba"), quantos objetos Agendamento existem na memória? testar
Ainda apenas um. O setter altera o valor de um atributo dentro do objeto já existente; nenhum new foi chamado nessa linha, então nenhum objeto adicional foi criado — apenas o estado do objeto original mudou.

Glossário

Uma cola de bolso com os termos usados nesta ficha, em uma frase cada.

Classe
O molde que define quais informações e ações um tipo de objeto vai ter.
Objeto
Uma instância concreta de uma classe, criada com new, com seus próprios valores.
Atributo
Um dado guardado dentro de um objeto (o "tem").
Método
Uma ação que um objeto sabe executar (o "faz").
Parâmetro
Um valor recebido de fora por um método ou construtor, para ele poder trabalhar.
this
Referência ao objeto atual — usada para diferenciar o atributo do objeto de um parâmetro de mesmo nome.
public
Modificador que permite acesso a partir de qualquer parte do programa.
private
Modificador que restringe o acesso direto apenas à própria classe.
Getter
Método público que devolve o valor de um atributo privado.
Setter
Método público que altera o valor de um atributo privado.
Encapsulamento
O objeto protege seu estado interno e controla como ele pode ser lido ou alterado.
Construtor
Bloco especial, com o mesmo nome da classe e sem retorno, que inicializa o objeto no momento em que ele nasce.
Sobrecarga
Ter vários métodos ou construtores com o mesmo nome, diferenciados pelos parâmetros.
Estado
O conjunto de valores que um objeto guarda em um dado momento — mudar um valor é "mudar de estado".
